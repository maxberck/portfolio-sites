# Coiffure 04 — Chromatic Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and publish `coiffure-04` Chromatic as a five-route fictional creative color studio demo using a Color Lab editorial collage system, distinct color-family compositions, a technical Color Map, contact-sheet work presentation, generated portfolio preview, and dedicated CI smoke coverage.

**Architecture:** Follow the repository pattern of thin Next.js App Router files under `app/sites/coiffure-04/**` and template-owned data, types, components, pages, theme, and stylesheet under `src/templates/coiffure-04/**`. Keep the site fully static and visually isolated from Maison Élise, District Cut, and Form Studio. Publication happens only after route/content checks are green, then `/public/previews/coiffure-04-home.webp` is generated through the existing preview workflow.

**Tech Stack:** Next.js 16.3.4 App Router, React 19.2.8, TypeScript 5, CSS, `next/font/google`, `next/image`, Node smoke scripts, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-11-coiffure-04-chromatic-design.md`

## Global Constraints

- Brand: `Chromatic`.
- Descriptor: `Creative Color Studio`.
- Direction: Color Lab editorial / artistic collage.
- Palette: paper `#F4F0E8`, near black `#111111`, utility gray `#77736D`, line gray `#D5D0C7`, fuchsia `#FF3EA5`, electric blue `#2F5BFF`, tangerine `#FF6A2A`, acid green `#C8FF36`.
- No gradients, glassmorphism, soft decorative blobs, generic SaaS cards, repeated equal feature cards, persistent side rail, serif-led luxury styling, or Swiss-grid imitation.
- Routes: `/sites/coiffure-04`, `/color`, `/studio`, `/work`, `/contact`.
- Desktop primary navigation is a small horizontal utility header.
- Every route inherits `robots: { index: false, follow: true }`.
- No backend, booking engine, live availability, account, payment, form, iframe, embedded map, geolocation, fake reviews, awards, certifications, founder history, or unsupported claims.
- Home service families are stable markers `01 BLONDE`, `02 COPPER`, `03 VIVID`, `04 CORRECTION`, each with a visibly different composition.
- Color Map stable stages are `DIAGNOSIS`, `BASE`, `TONE`, `CARE`.
- Work is editorial: oversized feature crop + contact-sheet groups + shade references, never a uniform gallery grid.
- Photography must be hair/color-specific; hair must be the visual subject.
- Existing Garage, Restaurant, Maison Élise, District Cut, and Form Studio product files remain untouched except shared portfolio verification counts when publication legitimately changes them.
- Accessibility: semantic headings, keyboard navigation, visible `:focus-visible`, adequate contrast on every color field, non-color active cues, practical touch targets, useful image alt text, reduced-motion support, and no information encoded only through swatch color.
- Final publication requires `public/previews/coiffure-04-home.webp` generated by the repository capture workflow.

- [ ] **Step 2: Build the hero as an art-direction composition**

Use one semantic `<h1>` containing visually separated `CHRO` and `MATIC` spans. The layout must include:

- one large paper field;
- one electric-blue or fuchsia hard block;
- one tangerine/acid marker;
- 2–3 hair-focused image crops in overlapping CSS grid/absolute layers;
- quiet intro copy and one CTA to `/sites/coiffure-04/color` or `/sites/coiffure-04/work`.

Do not use a standard 50/50 split hero.

- [ ] **Step 3: Implement four family variants without equal-card repetition**

`ColorFamilyPanel` accepts `family` plus variant:

```ts
variant: "portrait-right" | "texture-full" | "layered" | "technical"
```

Map the families exactly:

```ts
BLONDE -> "portrait-right"
COPPER -> "texture-full"
VIVID -> "layered"
CORRECTION -> "technical"
```

Each variant changes grid structure, image proportion, copy placement, and dominant field. Shared typography/data primitives are allowed, but the outer layout must differ.

- [ ] **Step 4: Implement Color Map**

Render four stage articles with named swatches/codes. Desktop uses a continuous horizontal composition rather than four cards. Mobile applies:

```css
.chrom-color-map-track {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x proximity;
}
```

Each stage retains a minimum readable width, visible stage name, description, and text labels for every swatch.

- [ ] **Step 5: Implement the work teaser**

`ContactSheet` renders one oversized feature image and a compact group of at least four smaller crops/references. Captions expose `ref`, `family`, and `shade`. Avoid equal-square gallery styling.

- [ ] **Step 6: Implement responsive/accessibility rules**

At desktop, preserve overlap and collage. At <=900px simplify overlapping layers without hiding essential copy. At <=720px turn accent zones into sectional full-width fields, keep display typography intentionally large, prevent page overflow, and keep touch targets practical.

Add:

```css
@media (prefers-reduced-motion: reduce) {
  .chromatic-site *,
  .chromatic-site *::before,
  .chromatic-site *::after {
    scroll-behavior: auto !important;
    transition-duration: 0.01ms !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
  }
}
```

Expected: lint/build pass; smoke progresses beyond 404s but can still fail on incomplete secondary pages/publication.
